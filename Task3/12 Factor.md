# Соответствие принципам Twelve-Factor
Целевая архитектура AdScale проектируется с соблюдением принципов Twelve-Factor App, что упрощает масштабирование, автоматизацию развертывания и обеспечение отказоустойчивости

## Фактор

### I. Codebase
Каждый микросервис (Bidding, Campaign, Finance, Analytics и др.) имеет собственный репозиторий и жизненный цикл
### II. Dependencies
Все зависимости управляются через package manager (Go Modules, npm, pip)
### III. Config
Конфигурация хранится во внешних переменных окружения, а не в коде
#### IV. Backing Services
PostgreSQL, Redis, Kafka и ClickHouse рассматриваются как подключаемые ресурсы
#### V. Build, Release, Run
Разделены стадии сборки, релиза и запуска через CI/CD
#### VI. Processes
Сервисы являются stateless и не хранят состояние локально
#### VII. Port Binding
Каждый сервис публикует собственный API (REST/gRPC)
#### VIII. Concurrency
Масштабирование осуществляется запуском дополнительных экземпляров сервисов
#### IX. Disposability
Поддерживается быстрое завершение и перезапуск контейнеров
#### X. Dev/Prod Parity
Используются одинаковые контейнерные образы для всех сред
#### XI. Logs
Логи пишутся в stdout и централизованно собираются ELK/OpenSearch
#### XII. Admin Processes
Миграции БД и административные операции выполняются как отдельные задачи


Целевая архитектура AdScale соответствует принципам Twelve-Factor App:
* сервисы являются stateless, * конфигурация вынесена во внешнее окружение,
*  все хранилища рассматриваются как подключаемые ресурсы, 
* масштабирование достигается добавлением экземпляров сервисов, 
* логирование и административные процессы централизованы.

Это обеспечивает переносимость, автоматизацию развертывания, отказоустойчивость и возможность масштабирования платформы до 50 000 RPS при SLA 99,9%
